# PostgreSQL Setup

The SQLAlchemy 2.0 async plumbing a service is wired with once: the declarative base, the engine and session factory, the two session providers, the Alembic config helper, and the primary-key choice. Load this when starting a project, or when changing who owns the request transaction.

Examples use `app/` as the top-level package. Substitute your package name if different.

## Declarative base

```python
from sqlalchemy import MetaData
from sqlalchemy.orm import DeclarativeBase

POSTGRES_INDEXES_NAMING_CONVENTION = {
    'ix': '%(column_0_label)s_idx',
    'uq': '%(table_name)s_%(column_0_name)s_key',
    'ck': '%(table_name)s_%(constraint_name)s_check',
    'fk': '%(table_name)s_%(column_0_name)s_fkey',
    'pk': '%(table_name)s_pkey',
}


class Base(DeclarativeBase):
    metadata = MetaData(naming_convention=POSTGRES_INDEXES_NAMING_CONVENTION)
```

The naming convention gives every index and constraint a deterministic name, so the name Alembic writes into a migration is the name the database already has and a later revision can drop it by that name. Without it, unnamed constraints get server-generated names that differ between environments.

Composite constraints still need an explicit `name=`, because the `uq`, `fk` and `ix` templates interpolate only the first column.

`Base.metadata` only knows about models whose module has been imported. Discover them instead of maintaining an import list, so a new model file cannot be forgotten and silently autogenerated as a table drop:

```python
# app/infrastructure/db/models/__init__.py
from pathlib import Path
import pkgutil


def load_all_models() -> None:
    package_dir = Path(__file__).resolve().parent
    modules = pkgutil.walk_packages(path=[str(package_dir)], prefix='app.infrastructure.db.models.')
    for module in modules:
        __import__(module.name)
```

`migrations/env.py` calls this before reading `Base.metadata`; see `reference/testing.md`.

## Engine and session factory

```python
from functools import lru_cache

from sqlalchemy.ext.asyncio import async_sessionmaker, AsyncEngine, AsyncSession, create_async_engine

from app.core.config import get_settings


@lru_cache
def async_engine() -> AsyncEngine:
    settings = get_settings()
    return create_async_engine(settings.DATABASE_URL.unicode_string(), pool_pre_ping=True)


@lru_cache
def async_session_factory() -> async_sessionmaker[AsyncSession]:
    return async_sessionmaker(bind=async_engine(), autoflush=False, expire_on_commit=False)
```

`lru_cache` makes both a lazy singleton: one connection pool per process, built on first use rather than at import, and clearable with `.cache_clear()` when tests point the application at a container.

`autoflush=False` because writes here are explicit Core `insert` / `update` / `delete` statements that execute the moment `session.execute()` or `session.scalar()` runs. Nothing sits pending in the unit of work, so there is nothing for an implicit flush to do except add surprise ordering.

`expire_on_commit=False` keeps loaded attributes readable after a commit. With the default, every attribute is marked expired and the next read issues a refresh query — which, under async, happens after the request scope has closed and fails.

## Session providers

```python
from collections.abc import AsyncGenerator
from contextlib import asynccontextmanager


async def get_session() -> AsyncGenerator[AsyncSession]:
    async with open_db_session() as session:
        yield session


@asynccontextmanager
async def open_db_session() -> AsyncGenerator[AsyncSession]:
    session: AsyncSession = async_session_factory()()
    try:
        yield session
    except Exception:
        await session.rollback()
        raise
    else:
        await session.commit()
    finally:
        await session.close()
```

`open_db_session` owns the transaction: commit on a clean exit, rollback on any exception, close either way. That is the whole reason services do not call `commit()` themselves — one owner, one decision point.

`get_session` is the FastAPI dependency. FastAPI caches a dependency's result per request, so every service injected into one request shares a single session and therefore a single transaction. Use `open_db_session()` directly outside a request: scripts, CLI commands, background jobs, lifespan startup.

Both are annotated `AsyncGenerator[AsyncSession]`. `AsyncGenerator` takes a yield type and a send type; the send type defaults to `None` on the 3.13 floor, and ruff's `UP043` flags an explicit `, None`.

## Alembic config

```python
from alembic.config import Config
from pydantic import PostgresDsn


def get_alembic_config(database_url: PostgresDsn, script_location: str = 'migrations') -> Config:
    alembic_config = Config()
    alembic_config.set_main_option('script_location', script_location)
    alembic_config.set_main_option(
        'sqlalchemy.url',
        database_url.unicode_string().replace('postgresql+psycopg', 'postgresql'),
    )
    return alembic_config
```

Building the `Config` in code rather than reading `alembic.ini` lets tests and startup migrations pass a database URL that only exists at runtime. The `+psycopg` driver marker is stripped because `migrations/env.py` builds a synchronous engine from this URL; the async driver belongs to the application engine, not to Alembic.

`script_location` resolves relative to the current working directory. Pass an absolute path when the caller may not be the repository root — a test run started from an IDE, for instance.

## Primary keys

An integer surrogate key is the house default. When a UUID is the right choice, the database generates it, which keeps the value out of application code entirely:

```python
# app/infrastructure/db/models/cover.py
from typing import TYPE_CHECKING
import uuid

from sqlalchemy import ForeignKey, func, Integer, String, Uuid
from sqlalchemy.orm import Mapped, mapped_column, relationship

from app.infrastructure.db.database import Base

if TYPE_CHECKING:
    from app.infrastructure.db.models.book import BookModel


class CoverModel(Base):
    __tablename__ = 'covers'

    id: Mapped[uuid.UUID] = mapped_column(Uuid, primary_key=True, server_default=func.uuidv7())
    book_id: Mapped[int] = mapped_column(Integer, ForeignKey('books.id', ondelete='CASCADE'), unique=True)
    image_url: Mapped[str] = mapped_column(String(512))

    book: Mapped['BookModel'] = relationship(back_populates='cover', lazy='raise')
```

`unique=True` on the foreign key is what makes this one-to-one rather than one-to-many.

`uuidv7()` is a server function of the major named in the skill's `> Requires` line. Against an older major, generate the key in Python instead — `default=uuid.uuid7` where the interpreter provides it, `default=uuid.uuid4` where it does not — and pin the test container image to the major production runs.

## Gotchas

- `get_settings().DATABASE_URL` is a `PostgresDsn`, not a string. Call `.unicode_string()` wherever a plain URL is needed; passing the object itself fails inside SQLAlchemy with `ArgumentError: Expected string or URL object`.
- Do not put `__abstract__ = True` on `Base`. A `DeclarativeBase` subclass is never mapped, so the attribute changes nothing; it only reads as if it mattered.
- Calling `async_engine.cache_clear()` drops the reference to the pool but does not close it. In tests, clear the caches before anything opens a connection, not after.
